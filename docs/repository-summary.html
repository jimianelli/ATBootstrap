Repository Summary

ATBootstrap on codex/R-convert

This branch converts the R side into a usable non-spatial parity layer, freezes the existing Julia outputs as regression targets, and makes the spatial simulator an explicit interface instead of a placeholder.

Repository: ATBootstrap Branch: codex/R-convert Focus: R conversion plus golden references

Repository Shape

The repository is still centered on the Julia implementation in src/ and the survey-specific Julia drivers in analyses/. This branch does not replace the Julia spatial simulator. It separates the repository into two clearer layers:

Portable layer Preprocessing, survey-grid setup, TS/selectivity/age-length/weight helpers, summaries, and non-spatial plotting are now available in R.
Unported layer GeoStats-based conditional simulation and class-problem spatial setup remain external to the R port.
Regression layer Existing Julia outputs are frozen under tests/golden/analyses_results/.

What This Branch Adds

  • A consolidated R implementation in R/funs.R that replaces the prior duplicate, partially placeholder code paths.
  • A compatibility entry point in R/ATBootstrap.R that simply sources the consolidated module.
  • A frozen copy of the current Julia result CSVs in tests/golden/analyses_results/, plus a checksum manifest.
  • A golden-reference verification script and a non-spatial smoke test.
  • This docs/ Pages surface so the branch can present a browser-friendly summary.

Current R Boundary

The branch intentionally stops short of reimplementing the Julia spatial simulator. In the new R path:

  • preprocess_survey_data() is real and writes the normalized survey files.
  • read_survey_files(), resampling helpers, TS/selectivity/age-length/weight logic, and summaries are real.
  • simulate_class_iteration() is real for the non-spatial parts and requires a supplied spatial simulator.
  • simulate_nasc() now fails clearly unless a real simulator or the required spatial objects are attached.
Meaning: this branch is suitable for parity work around preprocessing and downstream survey computations, but not yet for replacing the Julia geostatistical backend.

Validation Added Here

  • Rscript tests/check_golden_results.R verifies that the current Julia outputs in analyses/results/ still match the frozen golden copies.
  • Rscript tests/smoke_nonspatial_port.R exercises the non-spatial R pipeline on a temporary copy of one survey directory so tracked data files are not rewritten.
  • Rscript tests/generate_r_julia_parity_report.R generates a documented parity report and machine-readable evidence tables under docs/.

Why This Matters for the Larger Migration

The immediate program risk is still disagreement in point estimates between the uncertainty workflow and the standard survey outputs. That makes a clean separation of responsibilities more useful than a second model-framework rewrite.

  1. Freeze the current Julia outputs.
  2. Get the non-spatial R and survey-processing path into a maintainable state.
  3. Use that to reconcile point-estimate differences against Macebase Analysis.
  4. Only then decide whether the spatial layer should stay in Julia, move to R, or be redesigned.
