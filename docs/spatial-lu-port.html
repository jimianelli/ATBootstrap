Later Follow-up

This page captures the first LU-style R port. A later follow-up inspected Julia’s randprep(..., LUMethod(), ...) setup directly, rewired the R backend to match the same masked-domain conditional structure, and added intermediate-object probes for dlocs, slocs, conditional shifts, and factor summaries.

See Spatial Conditional Alignment for that second pass and the refreshed parity boundary.

What Changed

The R backend in R/funs.R no longer uses the Gaussian-copula field approximation that was added during the first spatial port pass. It now follows the same broad structure as src/spatial.jl:

  • fit the empirical exponential variogram,
  • build the conditional covariance of simulation locations,
  • factor that covariance into a lower-triangular matrix L,
  • solve L \ mu_x in R before parameterizing the nonnegative marginals,
  • simulate fields with L %*% z through nonneg_lumult().
Old path Correlation-Cholesky plus copula quantiles. This got means and variograms into the right range but selected the wrong marginal family for some classes.
New path Direct LU-style simulator in R with the same parameter flow used by Julia: mu_x, L, and nonnegative z draws.
Immediate effect The R backend now matches Julia’s chosen zdist family for all three tested 202207 classes.

Implementation Notes

The key R-side steps now live in R/funs.R:

  • get_lungs_params() stores the full conditional factor L.
  • parameterize_zdists() computes mu_z with forwardsolve().
  • nonneg_lusim() feeds marginal draws into nonneg_lumult().
  • simulate_class_iteration() now uses that deterministic field when simulate_nasc = FALSE.

Because the current R implementation constructs a plain conditional covariance and then clips negative outputs to zero, it is still not identical to Julia’s internal GeoStatsProcesses.LUMethod() behavior. That difference matters most for field spread.

Comparison Harness

Three comparison scripts were added so the backend can be checked repeatedly instead of by inspection:

  • tests/spatial_backend_probe.R records R class-level spatial diagnostics.
  • tests/spatial_backend_probe.jl records the same diagnostics from Julia.
  • tests/compare_spatial_backends.R joins both outputs and writes a parity table.

The wrapper command used for the latest run was: ATB_SPATIAL_NSIM=10 Rscript tests/compare_spatial_backends.R

Current Results

The latest comparison is based on survey 202207 and the three operational classes SS1, SS2, and BT.

Class R zdist Julia zdist Status Main remaining gap
SS1 inverse_gaussian Distributions.InverseGaussian PARTIAL Deterministic field SD still differs by about 25%.
SS2 gamma Distributions.Gamma DIVERGENT Field spread remains materially off even though means and variogram shape are closer.
BT inverse_gaussian Distributions.InverseGaussian DIVERGENT Spread and simulated-class totals remain too far from Julia.
Key improvement: the LU-style port fixed the previous mismatch in marginal-family selection. The remaining work is now more clearly about reproducing Julia’s field-spread behavior, not about whether R can support inverse Gaussian or the LU flow.
Current limit: this is still not sufficient to claim backend equivalence. The parity CSV shows that SS2 and BT remain outside a reasonable tolerance because the R field variance is still too different.

Next Step

The most defensible next pass is to target the spread gap, starting with SS2. That likely means reproducing more of Julia’s exact conditional-simulation preprocessing, rather than just matching the mathematical outline of L %*% z.

  • Inspect how Julia’s randprep(..., LUMethod(), ...) encodes the conditional problem.
  • Check whether the R path is missing a mean-centering or variance-normalization step before factorization.
  • Compare intermediate objects class-by-class, not only final bootstrap totals.
