Implementation Notes

Preprocessing Parity Notes

Focused notes on the preprocessing fixes needed to move the repository toward a full R implementation, with emphasis on the survey grid and projected trawl-location products.

What Changed

Ribbon geometry The R transect-ribbon domain builder now follows the Julia logic directly instead of buffering lines with round caps in sf.
Snapped transect axis The ordering coordinate is now snapped to the rounded transect grid before the ribbon polygon is built, matching the Julia preprocessing behavior.
Trawl output schema trawl_locations_projected.csv now restores the Julia-era helper columns lla and utm in addition to the operational coordinates.

Why These Fixes Mattered

The original R preprocessing mismatch was not a small numeric tolerance issue. It came from a different survey-domain construction rule:

  • the earlier R code used st_buffer() with round end caps,
  • the Julia code builds an explicit left/right ribbon polygon with flat ends,
  • the earlier R code also averaged the ordering coordinate instead of snapping it to the rounded grid.

Those differences changed the domain boundary enough to alter surveygrid.csv and to exclude some GAP haul locations from trawl_locations_projected.csv.

Current Status

  • surveygrid.csv now matches the Julia-era references in the parity report.
  • trawl_locations_projected.csv now matches on row counts, schema, and operational coordinates.
  • The remaining trawl-location mismatch is in the exact string serialization of lla and utm, because R and Julia print those helper objects differently.
  • acoustics_projected.csv still has partial parity for the checked surveys 200909, 201207, and 201807, so preprocessing work is not finished.
Interpretation: the survey-domain logic is now much closer to the Julia implementation, and the remaining preprocessing differences are narrower and easier to localize than before.

How To Re-check

  • Run Rscript tests/generate_r_julia_parity_report.R.
  • Review R and Julia parity evidence.
  • Use the preprocessing detail CSV to see survey-by-survey results.
